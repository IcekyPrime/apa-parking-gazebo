## 3. 常见故障

### 3.1 节点启动后「一个 topic 都不发」，`ros2 node list` 也看不到它

**原因**：WSL2 下 Fast-DDS 的共享内存传输残留，进程卡在 `rcl_node_init`（`ps` 里能看到进程活着、CPU 有占用）。

**处置**：

```bash
bash scripts/clean_env.sh
export FASTRTPS_DEFAULT_PROFILES_FILE=\
$HOME/apa_ws/install/parking_planner/share/parking_planner/config/fastdds_udp_only.xml
```

`scripts/run_demo.sh` 已内置该环境变量，正常走脚本不会遇到。

### 3.2 `ros2 launch` 报 `libexec directory … does not exist`

**原因**：`parking_planner` 缺少 `setup.cfg`，console_scripts 被装到 `bin/` 而不是 `lib/<pkg>/`。

**处置**：确认 `src/parking_planner/setup.cfg` 存在（内容为 `script_dir=$base/lib/parking_planner`），重新 `colcon build`。

### 3.3 `/scan` 全是 `inf`

**原因**：`gz sim --headless-rendering` 时 `gpu_lidar` 离屏深度纹理失效。

**处置**：不要加 `--headless-rendering`；在 WSLg 下（`DISPLAY=:0`）直接 `gz sim -s` 即可，脚本已这样配置。若仍无效，用 Xvfb：`Xvfb :99 -screen 0 1280x1024x24 & export DISPLAY=:99`。

### 3.4 `slam_toolbox` 刷 `Message Filter dropping message … queue is full`

**原因**：TF 时间轴断了（车辆静止时 `/odom` 不发布）。交付版本已修（`docs/04` A-1）；若仍有零星几条，属启动瞬间的正常现象。

### 3.5 车辆不动 / 走走停停

按顺序检查：

```bash
ros2 topic echo /parking_status        # 状态机是否卡在 SELECT_SPOT（没找到车位）
ros2 topic echo /control_mode          # 是否在 planner
ros2 topic echo /cmd_vel_planner       # 控制器输出是否为零
ros2 topic hz /cmd_vel                 # 仲裁后是否真的有 20 Hz 指令
```

* 卡在 `SELECT_SPOT`：说明车位都被判为 `occupied/blocked`，看 `/parking_free_space`（绿色=自由、红色=命中）与日志里的「车位占用评估」；
* `/cmd_vel` 有值但车不动：检查是否顶住了障碍（Gazebo 里车辆会「蹭」着障碍走，速度接近 0）。

### 3.6 `predictor_node` 报「未找到模型权重」

首次需要训练：

```bash
cd ~/apa_ws/training
python3 generate_dataset.py     # 生成 4900 条样本
python3 train.py                # CPU 约 3 分钟，val_ADE ≈ 0.32 m
```

或用 `PREDICT=false` 先跳过预测，泊车流程不受影响（风险恒为 `safe`）。

### 3.7 想用图形界面看

```bash
HEADLESS=false RVIZ=true bash scripts/run_demo.sh
```

RViz 里预置了：SLAM 地图、泊车路径、车位标记（绿/红/灰/蓝）、激光、TF。焦点视图默认俯视停车场中心。

## 附：三级规划相关的四个坑（都已在代码里修掉，改参数时别踩回去）

| 现象 | 根因 | 现在的处理 |
|---|---|---|
| 车斜着穿过人行道/绿化带，但曲率检查全部"通过" | 起点节点按「离自车距离 + 到目标的图距离」打分且**没有搜索半径**，目标附近的节点会飞过来接自车，路线退化成一条斜线 | 起点节点限制在 12 m 内，且首段方向必须与车头一致（反向惩罚 300 m）；主路节点按 9~10 m 一档布设 |
| 车在场内过道转过不去，横向偏差发散到 8 m，冲出停车场 | 转角用 Bezier 近似，实际半径只有切线长的 1/√2，场内 8 m 见方的过道只生成出 2 m 半径的圆弧 | 改成显式圆弧 `T = R·tan(φ/2)`，半径目标 6.04 m，按相邻边长自动收缩 |
| 路线里出现原地掉头 | 车道图没有方向、没有转向代价，Dijkstra 让车逆向或折返 | 主路两向做成**单向链**；Dijkstra 状态带「上一节点」，转角 > 90° 施加 800 m 等效代价 |
| 状态机卡在 `ROUTE` 不动，日志里既不报错也不前进 | 跟车器在终点前航向差太大时「既不算到位也不往前走」，`remaining` 恰好卡在阈值外 | 剩余距离阈值放宽到 2.5 m；另加「指令速度连续 6 s < 0.05 m/s 即判定卡死」的看门狗；偏差 > 2 m 且离终点还远时优先**重规划路线**而不是直接丢给 Hybrid A* |

### 场景侧（GUI 里能直接看到的三个现象）

| 现象 | 根因 | 现在的处理 |
|---|---|---|
| 行人一动不动 | Gazebo 的 `TrajectoryFollower` 靠给连杆**施加推力**追航点：不减速（实测冲过航点 4~16 m），而行人碰撞体是无轮圆柱，一碰到人行道 0.12 m 台阶就永久卡死 | 改用 `scene_agents/pedestrian_agent` 按固定速度调 gz 的 `/world/<world>/set_pose` 服务搬运（运动学）。launch 里多挂一个 `parameter_bridge` 桥这个服务，注意**服务桥必须写全请求和应答两个 gz 类型**：`/world/…/set_pose@ros_gz_interfaces/srv/SetEntityPose@gz.msgs.Pose@gz.msgs.Boolean`，少写应答类型会直接退出码 255 |
| 路口中间停着一辆橙黄色车，一直不动 | `traffic_car_b` 原来写死在 world 里（初值 -30,18.5 正好在西侧路口），而不开抢位场景时没有任何节点驱动它 | 从 world 里删掉，改成 `use_parker:=true` 时由 launch 用 `ros_gz_sim create` 生成，并由 `parker` 恒速开进 E8 |
| 报告 `DONE` 但车明明是斜的 | 车位内微调次数用尽后直接按当前位姿结束，状态仍置 `DONE` | 终态按 ≤0.35 m 且 ≤9° 判定：达标 `DONE`，否则 `INCOMPLETE`；航向差 >12° 时先退回预备位姿重新入位（最多 2 次） |

排查时可用的命令：

```bash
gz model -m pedestrian_sidewalk --pose        # 看行人当前位姿（隔 5 s 再看一次，应当有位移）
gz model --list | grep traffic                # 确认 traffic_car_b 只在 use_parker:=true 时存在
grep -a '入位' /tmp/demo.log                  # 看微调/退回重来/未达标的判定过程
```

另外：本机 WSL 只有 3.9 GB 内存，Gazebo + SLAM + 规划节点同时跑时余量很小。
`local_half_size`（局部栅格窗口半径）不要调到 20 m 以上，否则一次平行车位擦库
规划会吃掉几百 MB 并被 OOM 杀掉（表现是 `planner_node` 突然 `exit code -9`）。
