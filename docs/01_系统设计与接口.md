# 01 系统设计与接口契约

本文档是三方（A/B/C）联调的**唯一口径**：分层结构、话题契约、坐标系约定。三人各自的实现都以本文为准。

---

## 1. 分层结构

| 层 | 负责同学 | 核心节点 | 输出 |
|---|---|---|---|
| 仿真场景层 | A | `gz sim`（city_parking_lot.sdf）、`ros_gz_bridge` | `/scan` `/imu` `/odom` `/odom_gt` `/cmd_vel` |
| SLAM / 定位层 | A | `slam_toolbox`（Karto 前端 + SPA 位姿图后端）、`parking_slam/tf_bridge` | `/map`、`/vehicle_pose`、`map→odom→base_footprint→lidar_link` |
| 预测与风险层 | B | `detection_node`、`predictor_node`、`risk_node` | `/tracks`、`/predicted_trajectories`、`/risk_level` |
| 规划控制层 | C | `parking_planner`、`cmd_mux`、`parking_eval` | `/target_spot`、`/parking_path`、`/cmd_vel_planner`、`/control_mode` |
| 执行仲裁 | C | `cmd_mux` | `/cmd_vel`（唯一写入口） |

数据自下而上（传感器→地图/位姿→风险），控制自上而下（决策→规划→`/cmd_vel`）。

## 2. 话题契约

### 2.1 SLAM 层（A → 全体）

| 话题 | 类型 | 频率 | 说明 |
|---|---|---|---|
| `/map` | `nav_msgs/OccupancyGrid` | 1 Hz | slam_toolbox 输出，`frame_id=map`，0.05 m |
| `/vehicle_pose` | `geometry_msgs/PoseStamped` | 20 Hz | `frame_id=map`，自车中心位姿（含 yaw） |
| `/odom` | `nav_msgs/Odometry` | 50 Hz | 阿克曼插件轮式里程计（相对起步位姿） |
| `/odom_gt` | `nav_msgs/Odometry` | 30 Hz | 仿真真值世界位姿（仅用于调试/对照，不参与规划） |
| `/scan` | `sensor_msgs/LaserScan` | 10 Hz | 720 线，±180°，0.2–30 m，`frame_id=lidar_link` |
| `/driver_status` | `std_msgs/String` | 20 Hz | `running` / `done`，巡场结束信号（C 用它做控制权切换） |

### 2.2 预测与风险层（B）

输入：`/scan`、`/vehicle_pose`、`/target_spot`（C 提供）
输出：

| 话题 | 类型 | 说明 |
|---|---|---|
| `/tracks` | `prediction_interfaces/TrackedObjects` | 检测跟踪结果，车体坐标 |
| `/predicted_trajectories` | `prediction_interfaces/PredictedTrajectories` | 每目标未来 5 步（dt=0.4 s） |
| `/risk_level` | `std_msgs/String` | `safe` / `warning` / `danger` |

### 2.3 规划控制层（C）

| 话题 | 类型 | 方向 | 说明 |
|---|---|---|---|
| `/target_spot` | `geometry_msgs/PointStamped` | 发布 | 选定车位中心，`frame_id=map`，供 B 建泊车走廊 |
| `/parking_path` | `nav_msgs/Path` | 发布 | 规划路径（含换挡点） |
| `/control_mode` | `std_msgs/String` | 发布 | `idle` / `planner`，供 `cmd_mux` 仲裁 |
| `/cmd_vel_planner` | `geometry_msgs/Twist` | 发布 | 20 Hz，泊车控制量 |
| `/parking_status` | `std_msgs/String` | 发布 | JSON：状态机、目标车位、规划统计、误差 |
| `/parking_markers` | `visualization_msgs/MarkerArray` | 发布 | 车位（绿=空/红=占用/灰=不可见/蓝=目标）+ 目标箭头 |
| `/parking_free_space` | `nav_msgs/OccupancyGrid` | 发布 | 激光自由空间证据（-1 未知 / 0 自由 / 100 命中） |

## 3. 坐标系约定（三方已对齐）

```
map ──(slam_toolbox)──► odom ──(tf_bridge, 来自 /odom)──► base_footprint ──(静态)──► lidar_link
```

* **map 帧原点 = 自车出生位姿**（世界坐标 `(-9.5, -1.0)`，朝向 `-y`）。因此
  `p_map = R(-yaw₀)·(p_world − p₀)`，本文所有几何量（车位、障碍、路径、目标点）都在 map 帧。
* `base_footprint` = 车体中心（模型原点，z 投影到地面），**不是后轴**；规划的车体轮廓以它为几何中心。
* `lidar_link` 相对车体：`x=-0.15 m, z=0.72 m`，无旋转。
* B 的 `/tracks`、`/predicted_trajectories` 输出在 **车体（lidar_link）坐标**；C 若要用需自行变换到 map（当前 C 只消费 `/risk_level`，不需要变换）。

## 4. 数据流与状态机

```
        ┌──────────── 巡场建图（A 的 demo_driver）────────────┐
        │  /driver_status=running → C 保持 idle，不抢控制权     │
        └───────────────────────┬───────────────────────────┘
                                │ /driver_status=done
                                ▼
  WAIT_DATA ──(≥12 帧扫描)──► SELECT_SPOT ──(空闲车位)──► PLAN ──► FOLLOW ──► DONE
        ▲                          │  找不到                      │  ▲
        │                          └──(2 s 重试)──┐               │  │ danger 持续 6 s
        └────────── FAILED ◄──(黑名单耗尽)────────┘               └──┴── 重新规划
```

* `SELECT_SPOT`：用激光自由空间证据判定每个车位的 `free/occupied/blocked`，再按「前方、有助跑距离、距离近」打分选位；
* `PLAN`：优先「一把方向直接入库」（全前进无换挡），否则退化为两段式（先到车位正前方预备位姿，再直线入库）；
* `FOLLOW`：曲率前馈 + 横向/航向反馈跟踪；`danger` 立即停车等待，`warning` 降速到 45%；
* `DONE`：把终点误差、路径长度、换挡次数、耗时写入 `~/parking_eval.csv`。
